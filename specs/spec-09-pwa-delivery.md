# SPEC-09 — PWA Delivery & iOS Installability

- **ID**: SPEC-09
- **Feature**: Installable web app manifest, service worker, offline shell, iOS home-screen support
- **Target Lot**: Lot 6 (L6b) — the iOS delivery channel, alongside the Android APK (L6a)
- **Status**: 📝 DRAFT

---

## 1. Context & Goals

There is no way to install a native app on iOS without the App Store — no sideloading, no ad-hoc distribution short of a paid developer account. The only route is a **PWA added to the home screen from Safari**.

That has one consequence the project has to accept: the app shell must be served from an HTTPS URL. It does **not** weaken the privacy promise — only HTML, JS, CSS and the SQLite WASM binary are downloaded, once, then cached. No session data ever leaves the device.

The goal of SPEC-09 is to implement:
- A web app manifest and icon set.
- A service worker precaching the whole shell, so the app opens offline.
- The iOS-specific `<head>` and safe-area handling.

Android keeps the Capacitor APK (L6a) because native SQLite is a far sturdier store than IndexedDB. The PWA is the iOS channel, and would also work on Android as a fallback.

---

## 2. Domain Rules & Invariants

1. **The shell is cached, the data is not.** The service worker precaches build output only. `participations`, `sessions`, `players` live in IndexedDB via `jeep-sqlite` and are never touched by Workbox.
2. **`sql-wasm.wasm` must be precached.** It is not in Workbox's default glob. Without it the SQLite driver cannot boot and the app is a blank screen offline — the one failure mode that breaks the whole premise.
3. **The host must serve `.wasm` as `application/wasm`.** Any other MIME type and `WebAssembly.instantiateStreaming` refuses the module.
4. **SPA fallback required.** `navigateFallback: '/'`, otherwise reloading on `/standings` returns 404.
5. **`theme-color` is declared once per colour scheme.** A single value leaves the iOS status bar clashing with whichever theme the app renders (see [spec-07](spec-07-design-system-ui.md) §2.2).
6. **Icons are opaque.** iOS rejects transparency on `apple-touch-icon` and composites it on black.
7. **No install prompt nagging.** No custom "install me" banner: it is a single-user personal app, installed once.

## 3. Assets

Generated by `npm run icons` ([scripts/generate-icons.cjs](../scripts/generate-icons.cjs)), which has no dependencies — a raw RGBA buffer encoded as PNG with node's `zlib`.

| File | Size | Purpose |
|---|---|---|
| `favicon-32.png` | 32 | Browser tab |
| `apple-touch-icon.png` | 180 | iOS home screen (**iOS ignores the manifest icons**) |
| `icon-192.png` | 192 | Manifest |
| `icon-512.png` | 512 | Manifest, also declared `purpose: maskable` |

The mark is the **ScoreBar** — two thirds of solid `bib` yellow against one third of 45° hatching. It reuses the design system's signature element rather than inventing a logo, and it survives iOS's rounded-corner mask because the composition is full-bleed with no detail near the edges. Below ~72px the hatch lines would alias, so the generator falls back to a flat blend.

This is a placeholder in the sense that no visual identity exists yet, not in the sense that it is throwaway.

## 4. Configuration

`@vite-pwa/nuxt` (v1.1.1), configured in [nuxt.config.ts](../nuxt.config.ts):

- `registerType: 'autoUpdate'` — no "a new version is available" UI to build.
- `workbox.globPatterns` extended with `wasm`, and `maximumFileSizeToCacheInBytes` raised to 4 MB (the binary is 645 kB).
- `display: 'standalone'`, `orientation: 'portrait'`, `background_color` and `theme_color` on `--ground`'s dark value.
- `<link rel="manifest">` is declared **statically** in `app.head`: the module only injects it at runtime, and Safari's "Add to Home Screen" should not depend on hydration.
- `viewport-fit=cover`, so `env(safe-area-inset-bottom)` resolves. The 64px bottom nav pads itself by that inset and grows downwards rather than squeezing its icons under the iPhone home indicator.

---

## 5. Deployment

Any static host serves `.output/public` after `npm run generate`. Requirements: HTTPS, `.wasm` as `application/wasm`, SPA fallback to `index.html`.

Installation on iOS: open the URL **in Safari** (Chrome iOS cannot do this), Share → "Sur l'écran d'accueil".

---

## 6. Edge Cases & Error Handling

- **Safari and the installed app have separate storage.** Data entered in Safari before installing does **not** appear in the home-screen app. Not a bug: two sandboxes. This is the single most confusing behaviour to expect.
- **Storage eviction.** Safari purges script-writable storage after prolonged inactivity. Installed web apps are supposed to be exempt, but Apple's policy has shifted more than once and this has **not been verified on a device**. Treat the backup (SPEC-06) as the actual guarantee, not the browser. A season of statistics in an iOS IndexedDB with no backup is a gamble.
- **`saveWebStore()` matters more here than anywhere.** On iOS there is no native plugin: every write depends on it. On Android the same calls are no-ops.
- **A stale service worker** serving an old shell: `autoUpdate` handles it on the next launch, but a hard refresh may be needed once after a deploy.

## 7. Verification & Testing Plan

### Automated / local
- `npm run generate`, then serve `.output/public` and assert 200 + correct MIME for `/`, `/manifest.webmanifest`, `/sw.js`, `/sql-wasm.wasm`, and a deep link such as `/standings`.
- Assert `sql-wasm.wasm` appears in `sw.js`'s precache list.

### On device (not yet done)
- iPhone, Safari → add to home screen: correct icon, standalone (no Safari chrome), status bar matching the theme, nav clear of the home indicator.
- Airplane mode, cold start: app opens, fonts render in Archivo Expanded rather than a system fallback.
- Create a player, force-quit, reopen: the player is still there.
- Switch the phone between light and dark: all 25 screens follow.
